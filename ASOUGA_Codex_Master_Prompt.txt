1. تعليمات أساسية لا تقبل التفاوض
━━━━━━━━━━━━━━━━━━━━━━━━━━

1. نفّذ المشروع فعلياً داخل مجلد المشروع الحالي.
2. لا تكتفِ بإنشاء تصميم أولي أو Prototype.
3. جميع الصفحات والأزرار والتفاعلات يجب أن تعمل.
4. لا تستخدم أي صور إطلاقاً، سواء صور خارجية أو صور مولدة أو صور مخزنة.
5. أنشئ جميع العناصر البصرية برمجياً باستخدام CSS وSVG وCanvas وJavaScript.
6. لا تستخدم صور Unsplash أو Pexels أو أي روابط صور.
7. لا تختلق ذكريات أو مواقف حقيقية بين مهدي وغسق.
8. اجعل النصوص والذكريات والأسئلة قابلة للتعديل من لوحة الإدارة.
9. لا تضع أسراراً أو مفاتيح API أو كلمات مرور في الواجهة الأمامية.
10. لا تحذف ملفات المشروع الحالية قبل فحصها وفهمها.
11. حافظ على الملفات والبيانات الموجودة، ولا تستبدل أي إعداد مهم دون سبب.
12. اجعل الموقع سريعاً ومتجاوباً بالكامل مع الهواتف.
13. اللغة الأساسية عربية باللهجة العراقية، مع دعم الإنجليزية في العناوين والزخارف.
14. استخدم RTL بشكل صحيح في كل الواجهات العربية.
15. لا تختصر المشروع بسبب طوله؛ نفّذ جميع الأقسام المطلوبة.

# 9. الرسالة الكبرى
━━━━━━━━━━━━━━━━━━━━━━━━━━

هذا من أهم أجزاء المشروع.

أنشئ مشهداً سينمائياً يحتوي على:
- خلفية داكنة.
- ظرف فاخر ثلاثي الأبعاد.
- ختم يحمل حرف G.
- ورقة رسالة أنيقة.
- فتح الظرف بحركة واقعية باستخدام CSS.
- ظهور الرسالة تدريجياً.

استخدم النص التالي حرفياً كما هو، دون إعادة صياغة أو تصحيح للهجة أو حذف أو تغيير أي جملة:

من مهدي إلى اسوقة ♡

ما أعرف من وين أبدي، ولا شلون أرتّب الحچي حتى أوصفلج شكد أتمنى يكون هذا اليوم حلو عليج، وشكد أتمنى أشوف الفرحة بعيونج بكل لحظة منه.

كل عام وإنتِ بألف خير يا غسق، يا أجمل إنسانة دخلت حياتي، ويا صاحبة الاسم اللي صار إله مكان مختلف بگلبي.

يمكن بالنسبة للعالم اليوم مجرد يوم ميلاد، تاريخ جديد وسنة جديدة من عمرج، بس بالنسبة إلي هو يوم ميلاد إنسانة وجودها صار جزء حلو من أيامي.

تعرفين؟ مرات أفكر شلون بعض الأشخاص يكدرون يخلّون أبسط تفاصيل الحياة أحلى بمجرد وجودهم، وإنتِ بالنسبة إلي من هالأشخاص. حچيج، ضحكتج، طريقتج بالكلام، وحتى أبسط تفاصيلج، كلها أشياء أحبها وأتمنى تبقى دائماً جزء من أيامي.

وأما اسوقة...

هذا الاسم اللي أصيحلج بيه، واللي صار يحمل بداخله دلال ومشاعر خاصة ما تشبه أي شي ثاني. يمكن هو مجرد لقب بالنسبة للآخرين، بس بالنسبة إلي إله حكاية ومكانة غير عن كل الأسماء.

يا اسوقتي، أتمنى سنتج الجديدة تكون مليانة فرح ونجاحات وأشياء تشبه قلبج. أتمنى كل حلم تتمنيه يصير حقيقة، وكل أمنية مخبيتها بداخلج تلگى طريقها للنور، وأتمنى ما تشوفين من الأيام إلا كل شي يفرّحج ويطمن قلبج.

وأريدج تعرفين شغلة...

آني مو دا أكتب لج مجرد معايدة حتى أگول كل عام وإنتِ بخير وخلاص. آني أريدج تعرفين إن وجودج يعني إلي هواية، وإن إلج مكانة خاصة ما تكدر تختصرها رسالة أو كلمات مهما كانت طويلة.

يمكن مو دائماً أعرف أعبر بالطريقة الصح، ويمكن مرات الحچي ما يكفي حتى يوصل كل اللي بداخلي، بس أتمنى توصلج مشاعري من بين كل حرف كتبته إلج.

ولهذا سويت لج هذا العالم الصغير.

مو لأن المعايدات تحتاج مواقع، ولا لأن الحچي يحتاج مؤثرات حتى يصير حلو، بس لأن آني أردت أسويلج شي مختلف، شي يحمل اسمج، وتفاصيل تكتشفينها بنفسج، وذكرى تبقى مرتبطة بهذا اليوم.

لو أكدر أهديج شي ويا كل سنة جديدة من عمرج، جان أهديج أيام خالية من الهم، وأحلام تتحقق، وراحة تملأ قلبج، وضحكات ما تنتهي.

وأتمنى مهما كبرت السنين وتغيّرت الأيام، تبقين دائماً فخورة بنفسج، سعيدة بأحلامج، ومؤمنة إنج تستحقين كل الأشياء الحلوة.

كل عام وإنتِ غسق.

كل عام وإنتِ اسوقة.

وكل عام وإنتِ صاحبة مكانة خاصة بگلبي.

عيد ميلاد سعيد يا اسوقتي. ♡

ملاحظات إلزامية:
- بداية الرسالة تبقى «من مهدي إلى اسوقة ♡».
- لا تغيّر «هذا الاسم اللي أصيحلج بيه».
- لا تغيّر اللهجة العراقية.
- لا تستبدل اسوقة باسم آخر.
- لا تضف توقيعاً مختلفاً في نهاية الرسالة.
- اجعل القراءة قابلة للإيقاف والتسريع وإعادة التشغيل.

15. إدارة العمل والتوثيق
━━━━━━━━━━━━━━━━━━━━━━━━━━

اعمل على مراحل منظمة:

المرحلة الأولى: فحص المشروع وإعداد البنية.

المرحلة الثانية: الهوية البصرية والشاشة الافتتاحية والبوابة.

المرحلة الثالثة: العالم الرئيسي ومتحف الذكريات.

المرحلة الرابعة: الألعاب والمجرة.

المرحلة الخامسة: صندوق الأسرار والرسالة الكبرى.

المرحلة السادسة: الاحتفال النهائي.

المرحلة السابعة: لوحة الإدارة وقاعدة البيانات والأمان.

المرحلة الثامنة: الاختبارات والتحسينات النهائية.

بعد كل مرحلة:
- افحص التنفيذ.
- أصلح الأخطاء.
- حدّث ملف PROJECT_STATUS.md.
- اكتب ما اكتمل وما بقي.
- لا ترفع أي شيء إلى GitHub أثناء هذه المراحل.

إذا احتجت إلى معلومات أو بيانات غير متوفرة، لا تخترعها؛ أنشئ محتوى قابلاً للتعديل أو اطلب توضيحاً عند الضرورة.

16. تعليمات GitHub — الرفع النهائي فقط
━━━━━━━━━━━━━━━━━━━━━━━━━━

مستودع GitHub المطلوب:

https://github.com/jdjj47090-sketch/Happy-birthday.git

المطلوب الالتزام بالتعليمات التالية:

ممنوع رفع المشروع أثناء التطوير.

ممنوع تنفيذ Push بعد كل مرحلة.

لا تبدأ الرفع إلا بعد:
- اكتمال جميع أقسام المشروع.
- نجاح Production Build.
- نجاح الاختبارات الأساسية.
- إصلاح الأخطاء.
- التأكد من وجود الملفات المطلوبة.
- التأكد من عدم وجود أسرار أو بيانات حساسة.

عند الوصول إلى النهاية:

1. افحص git status.
2. افحص git remote -v.
3. تأكد من رابط المستودع.
4. تأكد من الفرع main.
5. افحص تاريخ المستودع البعيد والمحلي.
6. حافظ على جميع التغييرات والـ commits الموجودة.
7. لا تستخدم git push --force مطلقاً.
8. لا تحذف تاريخ المستودع.
9. لا ترفع ملفات .env أو مفاتيح API أو كلمات المرور أو Tokens أو مفاتيح SSH.
10. استخدم مصادقة GitHub الموجودة في البيئة، ولا تطلب مني إرسال كلمات مرور أو Tokens داخل المحادثة.
11. أضف الملفات المطلوبة فقط.
12. أنشئ Commit نهائياً واضح الاسم.
13. نفّذ Push إلى main.
14. تحقق من نجاح الرفع فعلياً.

إذا كان المستودع يحتوي على تغييرات أو تاريخ سابق، ادمج العمل بأمان. لا تستبدل المحتوى الموجود ولا تتجاوز التعارضات بالقوة. إذا ظهرت مشكلة تحتاج تدخلي، توقف واشرحها لي.

إذا لم يكن رابط المستودع صحيحاً أو تعذر الوصول إليه، لا تخمّن رابطاً بديلاً ولا ترفع إلى مستودع آخر.

بعد نجاح الرفع، أعطني:
- رابط GitHub.
- رقم آخر Commit.
- تأكيد نجاح Push.
- ملخص الملفات والأقسام التي تم رفعها.
- نتيجة Production Build.
- أي ملاحظات أو أجزاء لم تكتمل.

لا تقل إن المشروع رُفع إلا بعد التحقق من نجاح Push فعلياً.

17. النتيجة المطلوبة
━━━━━━━━━━━━━━━━━━━━━━━━━━

أريد مشروعاً متكاملاً بمستوى احترافي، وليس مجرد صفحة HTML بسيطة.

أريد تجربة تجعل غسق تشعر أن هناك عالماً كاملاً صُمم باسمها، وأن كل تفصيلة فيه لها معنى.

ابدأ الآن بفحص مجلد المشروع والملفات الموجودة، ثم نفّذ المشروع فعلياً خطوة بخطوة.

لا تتوقف عند التخطيط أو كتابة تقرير.
لا تكتفِ بإنشاء واجهات شكلية.
نفّذ كل ما تستطيع تنفيذه فعلياً، واختبره، ووثّق تقدمه.

وتذكّر: لا ترفع إلى GitHub إلا مرة واحدة في النهاية بعد اكتمال المشروع والاختبارات.
